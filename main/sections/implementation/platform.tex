\section{The Emulation Platform}\label{sec:impl-platform}

We implement our fuzzer on top of the MOGI emulation framework\todo{cite mogi}.
MOGI supports CPU and MMU emulation for various architectures and includes
instrumentation support as well as the possibility for emulating Linux userspace
binaries.

\input{figures/platform-architecture}

\begin{itemize}
  \item MOGI is a multi-crate Rust workspace for emulator-based binary analysis;
        \cref{fig:platform-architecture} shows the layers it is built from ---
        the lower half of the stack of \cref{fig:system-architecture}.
        \todo{cite: MOGI itself --- no entry in the bibliography yet}
  \item The layers, top to bottom:
    \begin{itemize}
      \item \emph{Setup} --- \code{mogi\_sysroots} composes a guest root
            filesystem from checked-in Dockerfiles, one staged \code{Case} per
            target (\cref{chap:targets}); \code{mogi\_quickstart} assembles CPU,
            MMU, scheduler and system services behind a single builder and fixes
            the defaults: an Ubuntu~25.10 base, an x86-64 guest, a
            \SI{1}{\gibi\byte} in-memory guest filesystem, a fixed clock epoch
            and a fixed PRNG seed (\cref{sec:platform-determinism}).
      \item \emph{Emulator core} --- \code{mogi\_emulator} models a Linux
            user-space system: an ELF loader, a scheduler with syscall dispatch,
            a virtual filesystem, a file-descriptor table, standard I/O, a TCP/UDP
            stack with netlink and event polling, a clock, seeded per-task PRNGs,
            and a task manager that parks and wakes tasks
            (\cref{sec:platform-emulation}).
      \item \emph{Seam} --- \code{mogi\_system} holds only traits: \code{CPU},
            \code{Hooks}, \code{MMU} and \code{Restorable}. Everything above the
            seam is written against them, which is what makes the execution
            backend interchangeable without touching the guest model.
      \item \emph{Backends} --- \code{mogi\_unicorn} wraps the external Unicorn
            engine, itself built on QEMU's dynamic
            translator~\cite{bellard_qemu_2005}
            \todo{cite: Unicorn (Quynh and Vu, Black Hat 2015) --- missing}; the
            native alternative is \code{mogi\_cpu} (interpreter plus an x86-64
            JIT) over \code{mogi\_mem}, lifting guest code from Ghidra SLEIGH
            processor specifications through \code{mogi\_sleigh} and
            \code{mogi\_lifter} \todo{cite: Ghidra / SLEIGH --- missing}.
      \item \emph{Guest} --- an unmodified x86-64 Linux user-space binary; no
            source instrumentation and no recompilation are required, which is
            what admits the targets of \cref{chap:targets}.
    \end{itemize}
  \item The emulator is driven through one interface: \code{Emulator::run},
        bounded by a timeout or an instruction budget, returning one of five
        \code{ExitReason}s --- all tasks exited, budget exhausted, every task
        blocked on I/O, a runtime error, or a breakpoint. Around it sit the
        handles to the system components (standard input, sockets, filesystem,
        clock), the hook registration of \cref{sec:platform-coverage}, and the
        snapshot pair of \cref{sec:platform-snapshots}.
  \item Emulating the system rather than only the CPU is what makes the platform
        usable here: the guest's I/O has no host counterpart, so its standard
        input and its sockets are buffers the host writes into and reads out of
        directly, and its clock and random sources are fixed rather than
        ambient.
  \item Scope --- MOGI is larger than what this thesis uses: it also carries
        fuzzing components, state-learning crates and the \code{lscale}
        application, none of which the experiments reported here build on.
        \todo{cite: L-SCALE (AST 2026) --- missing, if it is to be mentioned}
\end{itemize}
