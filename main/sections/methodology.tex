\chapter{Experimental Methodology}\label{chap:methodology}

Due to the high variance of RL algorithms, we run each corpus-action experiment using four
different PRG seeds.
We first show that the input-action targets can be successfully learned.
This serves as a correctness test for our EfficientZero implementation.
Since we will mainly focus on corpus-level actions, we will not do a parameter study,
but instead stop once the target is successfully learned.
For the same reason each input-action target is a single run on a single seed: what they answer
is whether the learner solves the target at all, not how much a solved target varies between
seeds, so no input-action result is stated with a seed spread.
For the corpus-level action targets, we do a detailed ablation study on the cJSON target (\cref{sec:target-cjson}).
We then use its parameters to test two additional targets, libxml2, as well as picohttpparser.

Experiment results are extracted using hooks (see~\cref{hooks}), either
during training for metrics like losses, or after training and during
evaluation for more expensive data collection like seed persistence.
Because of our architecture, we can easily evaluate new targets by using the existing
hook and evaluation infrastructure.

\section{Experimental Setup}\label{sec:methodology-setup}

The Burn deep learning framework itself supports multiple backends.
We run our experiments on devices that all have access to NVIDIA GPUs and therefore use
the CUDA backend.
Experiments were run on two VMs with an Intel(R) Xeon(R) Gold 5418Y processor as
well as an NVIDIA L40S and 500 GiB of RAM.
This allows us to run about two to four experiments of a campaign at once.
The exact version of libraries used is saved in the corresponding repository's
\code{Cargo.lock} file.

\subsection{Parameters}

There are many possible parameters to tune in this work.
We decide to mostly adopt the default EfficientZero parameters without any further studies
since the authors have already done a detailed investigation and found these to be good.
Two things we change are the temperature schedule $T:\mathbb{N}\rightarrow\mathbb{R}$ as well as
the root Dirichlet noise of \cref{eq:ez-dirichlet}, both its concentration $\xi$ and the fraction
$\rho$ it is mixed into the priors with, since we found fuzzing with large action spaces to require
more exploration.
The default EfficientZero parameters we adopt can be found in \cref{tab:app-ez-params}.

Parameter configuration is only done for the corpus-level action target cJSON.
Its result is then used for the two other corpus-level action targets.
Input-level action targets are executed using sensible parameters, but are not
explored further.

\section{Metrics}\label{sec:methodology-metrics}

We collect data at various points as described in~\cref{sec:impl-probes}.
What we are most interested in is the reward over time as well as the actual
coverage attained.
We further record EfficientZero-specific metrics like the loss curves of the
various models as well as the taken-action as well as MCTS visit count action
entropy to decide whether a policy has collapsed or is still in a state of
exploration.
From this information, we can show at what exact point the learner has first
encountered promising seeds and whether the learner was able to hold on to
these seeds without collapsing and giving up exploration.
Since we run each corpus-action experiment with multiple PRG seeds, we also show the variance of
the results to quantify whether re-running a campaign that has converged to a suboptimal
solution might be useful.
Action entropy is pooled over the positions of an episode, so it measures per-state determinism
only on a target whose optimal action does not depend on the position; where it does, the
per-position visit entropy is the quantity that separates a converged policy from a collapsed one.
We also measure the structural byte rate to verify that the fuzzer learns to
supply the PUT with relevant bytes only, as well as the number of steps inside
the replay buffer that carry a non-zero reward.
By measuring the KL divergence between the MCTS visit count distribution and the
policy priors, we can quantify the effectiveness of planning, i.e., by how much
planning through \gls{mcts} \enquote{moves} the policy.

The metrics described above can be found in~\cref{chap:results}.
Additional data is included in the Appendix.
